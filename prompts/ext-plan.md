# /ext-plan — план обновления через расширение

Составь только план. Файлы не меняй, пока пользователь отдельно не подтвердит запись.

Когда вызывать: нетиповое обновление, объекты на поддержке изменены и у поставщика, и локально.

Порядок:

1. Назови базу и расширение из `.dev.env` по именам ключей, без паролей и без строки подключения.
2. Список объектов, которые затронуты дважды. Если список неизвестен, скажи, какого сравнения не хватает, и остановись.
3. Для объектов на поддержке путь один: заимствование в расширение и точечная правка метода инструментами навыка `1c-metadata-manage` (`cfe-borrow`, затем `cfe-patch-method`). Основную конфигурацию не правь.
4. Не вызывай объединение конфигураций поставщика (`MergeCfg`) и не предлагай снять объект с поддержки, чтобы обойти запрет.
5. В конце перечисли команды навыка, которые понадобятся на применении. Сам их не запускай в этом ходе.

Ответ по-русски: объекты, почему расширение, какие команды потом, что останется нетронутым.
