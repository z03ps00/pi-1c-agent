# Vanessa Automation

> Адаптация MIT-навыка [yellow-hammer/skills-vanessa-automation](https://github.com/yellow-hammer/skills-vanessa-automation). Copyright (c) 2026 Ivan Karlo. Текст лицензии — `LICENSE` в этом каталоге. Обработка Vanessa Automation в профиль не входит.

Если в сессии есть инструменты Vanessa MCP, этот навык не ведёт работу. Пиши и гоняй сценарий по `skills/vanessa-mcp/SKILL.md`: состояние, шаги из библиотеки MCP, `check_syntax`, `run_scenario`. Здесь — файлы `.feature` и прогон `vrunner`, когда MCP не подключён.

Новые сценарии клади в `tests/features/`. Если в проекте уже есть дерево `features/**` или каталог вроде `Экспортные сценарии/`, пиши туда же и новое дерево не заводи. Это Gherkin на русском. Библиотека шагов уже есть в Vanessa Automation: новый текст шага бери из соседних фич проекта. Не придумывай формулировку, которой в проекте нет. Фичи пакетов OneScript с `# language: ru` — это 1bdd, не Vanessa.

## Каркас фичи

Один рабочий каркас, не единственный:

```gherkin
# language: ru
@tree

Функционал: Список контрагентов
	Как Разработчик
	Я хочу чтобы список открывался без ошибок
	Чтобы пользователь видел записи

Контекст:
	Дано Я запускаю сценарий открытия TestClient или подключаю уже существующий
	И я закрываю все окна клиентского приложения

Сценарий: Открытие списка
	Когда я открываю навигационную ссылку "e1cib/list/Справочник.Контрагенты"
	Тогда открылось окно 'Контрагенты'
	И я закрываю окно 'Контрагенты'
```

Шаги, которые уже есть в соседних фичах этого проекта, не заменяй шагами из другого репозитория.

Сценарий проверки — это файл `.feature`. Модуль `.bsl` его не заменяет. Шаг `И я выполняю код встроенного языка` в проверку не пиши.

Печатную форму не считают проверенной тем, что её открыли. После формирования сравни табличный документ с эталоном. Эталон — отдельный файл `.mxl` рядом с фичей, не фрагмент кода и не таблица, набранная в шаге вместо файла. Имя реквизита бери с формы печати. Шаг движка: `Дано Табличный документ "ИмяРеквизита" равен макету "Эталон.mxl"`. В параметре макета допустим путь к файлу, в том числе `содержит строки из макета`.

`@tree` частый, но не обязательный: при `ТегTreeВключенПоУмолчанию` иерархия работает и без него. Заголовок файла бывает `# language: ru` и `#language: ru`. Загрузчик считает языком строку, которая начинается с `#` и содержит `language:`. Заголовок фичи — `Функционал:` или `Функциональность:`.

Клиента подключай шагом из соседних фич. Один вариант — открыть уже существующий TestClient. Другой — именной: `И я подключаю TestClient "Имя" логин "..." пароль "..."`.

Библиотека экспортных сценариев помечена `@ExportScenarios`. Движок сравнивает тег в нижнем регистре, `@exportscenarios`. Без этого тега сценарии файла не становятся шагами. Имя сценария и есть вызываемый шаг. Параметр в заголовке в кавычках, в теле — в квадратных скобках `[Имя]`. На библиотеку часто вешают `@IgnoreOnCIMainBuild`: это не сценарий проверки.

Если в проекте два файла настроек, у подготовки и основного прогона разные списки тегов. В JSON имя тега без `@`, в фиче — с `@`. Не выдумывай новый тег подготовки, если в проекте его нет.

## Подготовка базы

Подготовка и проверка — разные фичи. Подготовка идёт по тегу, который уже отбирает её файл настроек.

Скалярные константы и эталонные справочники загружай шагами. Источник значений — файл рядом с фичами, не модуль. Шаги [генератора тестовых данных](https://pr-mex.github.io/vanessa-automation/TestDataGenerator/): `И я перезаполняю константу "Имя" значением "Значение"` и `И я проверяю или создаю для справочника "Имя" объекты`. Если в проекте уже есть свой экспортный шаг записи константы, вызывай его, новый блок кода не открывай.

Ссылочные константы ставь после справочников, на которые они смотрят.

Код `И я выполняю код встроенного языка на сервере` в подготовке — когда шага недостаточно: окно ИТС, загрузка из поставляемого классификатора, запись, которую подписка пускает только в режиме загрузки. В сценарии проверки этот шаг не пиши.

`КаталогФич` бывает каталогом или одним файлом. Выгрузка формы часто вложена (`ВыполнениеСценариев`, `КлиентТестирования`, `ОтчетJUnit`), бывают и плоские ключи. Булево пишут `true` или строкой `Истина`.

## Запуск

`vrunner test vanessa` по умолчанию открывает `bddRunner.epf` из пакета `add`. Vanessa Automation — это другая обработка. В профиле runner 3 путь задаёт `bddrunner-path`, в runner 2 — `--pathvanessa`. Файл настроек: `vanessasettings` или `--vanessasettings`. Типичный путь к одной EPF — `oscript_modules/vanessa-automation-single/vanessa-automation-single.epf`, но бери тот, который уже записан в профиле проекта.

`vrunner vanessa` в 2.x переименована в `vrunner test vanessa`. Один файл или каталог передаётся `--feature-path` (в 2.x это `--path`) и перекрывает `КаталогФич`. Опция не повторяется: несколько разрозненных файлов идут отдельными сеансами.

Прямой запуск обработки: `/Execute vanessa-automation.epf /C"StartFeaturePlayer;VAParams=..."`. Без `StartFeaturePlayer` сценарии не бегут. `VBParams` — устаревшее имя параметра `VAParams`.

Файл настроек Vanessa Automation не путай с `vb-params.json` Vanessa-ADD. Отбор тегов в файле настроек не дублируй флагами `--tags-filter`, если проект уже задал его в JSON.

Прогоны по одной информационной базе идут по очереди. Если окно 1С после сценария не закрылось, сеанс завис. Второй прогон в ту же базу при живом клиенте не запускай.

## Чеклист фичи

- Первая строка: `# language: ru` или `#language: ru`. Рядом часто `# encoding: utf-8`. Фича OneScript с таким заголовком — это 1bdd, не Vanessa.
- `@tree` частый. Если в `VAParams` включён `ТегTreeВключенПоУмолчанию`, фича без этого тега тоже иерархическая.
- Заголовок фичи: `Функционал:` или `Функциональность:`. Новые фичи клади в `tests/features/`. Каталог `features/`, корень репозитория или `Экспортные сценарии/` — только если проект уже так устроен.
- Клиента подключай тем шагом, который уже есть в соседних фичах. Именной клиент выглядит так: `И я подключаю TestClient "Имя" логин "..." пароль "..."`. Не подменяй его шагом из другого проекта.
- Библиотека с `@ExportScenarios` отдаёт сценарии как шаги. Имя сценария — текст шага, параметр в теле пишется `[Имя]`. На такой файл часто вешают `@IgnoreOnCIMainBuild`.
- Текст шага копируй из существующих `.feature` этого проекта. Новую формулировку добавляй только вместе с реализацией шага.
- Сценарий проверки — файл `.feature`. Модуль `.bsl` и шаг `И я выполняю код встроенного языка` проверку не заменяют.
- Подготовка базы — отдельная фича с тегом из её файла настроек. Константы: `И я перезаполняю константу "Имя" значением "Значение"`. Справочник: `И я проверяю или создаю для справочника "Имя" объекты`. Значения бери из файла-эталона. Ссылочные константы — после этих справочников.
- Код на сервере в подготовке — окно ИТС, классификатор поставки или запись только в режиме загрузки. Свой шаг записи константы, если он уже есть, не дублируй новым кодом.
- Печатную форму не оставляй на шаге открытия. Сравни табличный документ с файлом `.mxl` рядом с фичей: `Табличный документ "ИмяРеквизита" равен макету "Эталон.mxl"`. Эталон не собирай кодом.
- В списке тегов JSON имя без `@`. Не добавляй тег подготовки, которого в проекте нет.
- Заголовок окна в шаге `открылось окно` бери с формы, а не выдумывай.

## Чеклист прогона

- Файл настроек сценариев не смешивай с файлом инициализации: отбор тегов второго в основной не переноси.
- `vrunner test vanessa` по умолчанию открывает `bddRunner.epf` пакета `add`. Для Vanessa Automation в профиле задай путь к `vanessa-automation-single.epf`: `bddrunner-path` в runner 3, `--pathvanessa` в runner 2.
- `КаталогФич` бывает каталогом или одним файлом. `--feature-path` (в runner 2 это `--path`) его перекрывает.
- Выгрузка формы часто вложена (`ВыполнениеСценариев`, `КлиентТестирования`, `ОтчетJUnit`). Булево пишут `true` или строкой `Истина`.
- Прямой запуск: `/Execute vanessa-automation.epf /C"StartFeaturePlayer;VAParams=..."`. Без `StartFeaturePlayer` сценарии не бегут. `VBParams` — устаревшее имя параметра.
- `ЗавершитьРаботуСистемы` и `ЗакрытьTestClientПослеЗапускаСценариев` оставляй включёнными.
- Одна информационная база — один сеанс. Живое окно 1С значит, что предыдущий прогон не закончился. Второй прогон в ту же базу при живом клиенте не запускай.
