# Интеграция MCP Toolkit (ROCTUP) + Конвертация данных 2 / 3

Пошаговая инструкция для **проекта 1С**, который включил KD extras. Скиллы живут в профиле:

- `$PI_CODING_AGENT_DIR/skills/1c-mcp-toolkit/`
- `$PI_CODING_AGENT_DIR/skills/kd2-rules/`
- `$PI_CODING_AGENT_DIR/skills/kd31-rules/`

`/init` **не** копирует эти деревья в проект.

Репозиторий обработки: [ROCTUP/1c-mcp-toolkit](https://github.com/ROCTUP/1c-mcp-toolkit).

Это **не** Vanessa MCP и **не** `1c-data-mcp` (HTTP-сервис `hs/mcp` в конфигурации). Toolkit — внешняя обработка в клиенте 1С, HTTP API. В default `mcp.json` его **нет**.

Профиль **не** кладёт `MCP_Toolkit.epf` в git. Скачивать EPF только если пользователь явно подтвердил бинарник в этом запуске.

---

## 1. Данные проекта (не скилл)

После KD≠none `/init` (или later-enable):

| Путь | Назначение |
|------|------------|
| `tools/mcp-toolkit/` | Сюда пользователь кладёт `MCP_Toolkit.epf` (ОС-зависимый ассет) |
| `.dev.env` → `MCP_TOOLKIT_PORT` | 6003, если ключа не было |
| `.dev.env` → `KD2_PORT` | 7003, если выбрали КД 2 / both |
| `.dev.env` → `KD31_PORT` | 6011, если выбрали КД 3 / both |

Нативная компонента **зависит от ОС**. Linux-ассет не открывать в Windows-клиенте и наоборот. Версия платформы: `PLATFORM_PATH` в `.dev.env`.

---

## 2. Подготовка ИБ КД

Нужна информационная база «Конвертация данных» 2.1 или 3.1 — **тестовая копия**. Профиль не создаёт эту ИБ сам. Не писать в unnamed production.

1. Открой ИБ КД в **тонком или толстом** клиенте (веб-клиент нативную компоненту не грузит).
2. Файл → Открыть → `tools/mcp-toolkit/MCP_Toolkit.epf`.
3. Вкладка «Подключение»: встроенный сервер, порт из `.dev.env`.
4. Нажми «Запустить сервер».
5. Для **записи** правил сними защиту на ключевые слова `Записать`, `Удалить`, `УстановитьПривилегированныйРежим`. Без этого работают только запросы.

Обработку в конфигурацию **не** добавлять.

---

## 3. Проверка с той же машины

POSIX:

```bash
bash "$PI_CODING_AGENT_DIR/skills/1c-mcp-toolkit/scripts/health-probe.sh"
```

Windows: follow `powershell-windows`; `.\health-probe.ps1` (native HTTP, not ambiguous `curl`).

Пока сеанс 1С закрыт или сервер не запущен — агент КД не должен выдумывать результаты запросов.

## 4. Порты

Ключи в проекте `.dev.env` (профиль дописывает **только отсутствующие** после KD≠none). Не патчить `ai_rules_1c` `.dev.env.example`. Сниппет: `$PI_CODING_AGENT_DIR/dev.env.lab-extras.example`.

| Ключ | Типичное значение |
|------|-------------------|
| `MCP_TOOLKIT_PORT` | 6003 |
| `KD2_PORT` | 7003 |
| `KD31_PORT` | 6011 |

Две ИБ КД — два сеанса с разными портами.

---

## 5. Нет записи в mcp.json

Отдельной записи MCP для toolkit **нет**: агент ходит HTTP на `localhost:<порт>`. Fallback на `1c-data-mcp` (`vcexecutequery` / `vcexecutecode`) — **только после явного согласия**.

Работа с правилами:

- КД 2.0 — `$PI_CODING_AGENT_DIR/skills/kd2-rules/SKILL.md` (helpers, не сочинять BSL).
- КД 3.1 — `$PI_CODING_AGENT_DIR/skills/kd31-rules/SKILL.md` (паттерн `_Отправка` / `_Получение`).
