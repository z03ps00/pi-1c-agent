# YAxUnit

> Адаптация MIT-навыка [yellow-hammer/skills-yaxunit](https://github.com/yellow-hammer/skills-yaxunit). Copyright (c) 2026 Ivan Karlo. Текст лицензии — `LICENSE` в этом каталоге. Движок YAxUnit в профиль не входит.

Тесты живут в общем модуле тестового расширения. Движок и расширение с тестами лежат в `tests/cfe/<каталог>`. Имя расширения берётся не из имени каталога: в выгрузке конфигуратора это `Configuration.xml`, в EDT это `src/Configuration/Configuration.mdo`.

Перед прогоном оба расширения загружены в информационную базу, безопасный режим выключен. Движок ставится в каталог вроде `tests/cfe/YAXUNIT`. Если каталог с тем же именем расширения уже есть, обновляй его, а не создавай второй.

## Регистрация

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты
		.ДобавитьТест("СложениеЧисел")
		.ДобавитьТест("ДелениеЧисел", "Деление без остатка возвращает целое число", "Позитив");

КонецПроцедуры

Процедура СложениеЧисел() Экспорт

	ЮТест.ОжидаетЧто(2 + 2)
		.ИмеетТип("Число")
		.Равно(4);

КонецПроцедуры
```

`ДобавитьТест(ИмяТестовогоМетода, ПредставлениеТеста = "", ТегиСтрокой = "", Контексты = Неопределено)`. Теги в строке разделяются запятыми. `ИмяТестовогоМетода` совпадает с экспортной процедурой теста. Без четвёртого аргумента тест идёт во все контексты модуля. Серверный тест ограничивай строкой `"Сервер"`.

В `ИсполняемыеСценарии` данные не создают. `УдалениеТестовыхДанных()` удаляет только объекты, созданные через `ЮТест.Данные()`.

Утверждения цепляются цепочкой с новой строки: `.Равно()`, `.ИмеетТип()`, `.ИмеетДлину()`, `.Содержит()`.

## Конфиг

`tools/yaxunit.json` задаёт отчёт и завершение сеанса: `closeAfterTests` оставляй `true`, иначе окно 1С не закроется. `filter.extensions` - имя расширения из метаданных, не имя каталога. Если прогон передаёт свой фильтр модуля, список в json его не заменяет.

Транзакция у движка по умолчанию выключена. Включай её `.ВТранзакции()` при регистрации или ключом `settings.ВТранзакции`. Флаг действует на сервере и на толстом клиенте.

В `autumn-properties.json` секция `vrunner.test.yaxunit`: `yaxunit-config`, `report-format`, `report-path`. vanessa-runner 3 читает секцию сам: `vrunner test yaxunit`. vanessa-runner 2 запускает `vrunner run --command RunUnitTests=<путь к yaxunit.json>`.

Прогоны по одной базе идут по очереди. Незакрытое окно 1С означает зависший сеанс. Второй прогон в ту же базу при живом клиенте не запускай.

## Чеклист

- Модуль регистрирует тесты в `ИсполняемыеСценарии` через `ЮТТесты.ДобавитьТест("ИмяПроцедуры")`. В этой процедуре данные не создают.
- Процедура теста экспортная, имя совпадает с регистрацией.
- Проверки: `ЮТест.ОжидаетЧто(Значение).Равно(Эталон)`.
- Расширение с тестами лежит в `tests/cfe`. Имя берётся из `Configuration.xml` или, в EDT, из `src/Configuration/Configuration.mdo`, не из имени каталога.
- В `tools/yaxunit.json` держи `closeAfterTests: true`.
- Движок YAxUnit и расширение тестов загружены в базу до прогона.
